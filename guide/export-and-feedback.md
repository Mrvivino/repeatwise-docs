## Export schedules
On the schedule list, **Export** (next to the filters) saves the schedules shown with the current filters as a CSV file, for example `repeatwise-schedules-2026-10-07.csv`. Each line has the name, project, status, the rule in words, the time zone, the next run (in UTC and in the schedule's time zone), the last run (UTC, status and issue key), the owner and the labels.

The owner column says **You** for your own schedules and is empty otherwise: the list never receives other people's names or account ids, so the file does not contain them either.

## Import schedules
On the schedule list, **Import** (next to **Export**), or **Import from CSV** when you have no schedules yet, creates schedules from a CSV file: the RepeatWise template, a schedule export, or a sheet you filled in yourself. It is meant for moving rules from Jira's "Set to recur", other apps or spreadsheets (see [Migrating](migrating.html)).

1. Click **Import**, then **Download template** (or **Copy template** if your browser blocks downloads). Fill one line per schedule and delete the three example lines.
2. Pick the file, or paste its content and click **Check pasted CSV**. A file holds at most 200 schedules and 1 MB.
3. Read the preview. Each line shows its status: **Ready**, **Error** (with the exact reason, for example `Issue type "Story" does not exist in OPS. Available: Task, Bug.`), or **Skipped** when a schedule with the same name already exists in the same project, or appears earlier in the file. Tick **Import anyway** to create those too.
4. Click **Create N schedules**. Schedules are created one at a time with the same checks as the wizard: you need the same permissions, and you become the owner of each one. **Stop** finishes the current schedule and stops. The preview shows each result; a line that failed shows why.

Nothing is created for a line with an error. Fix the file and import it again: lines already created are skipped as duplicates, so nothing is created twice. Imported schedules start active, with no sub-tasks, sprint or custom fields; edit a schedule afterwards to add them.

The file is read in your browser; RepeatWise sends it nowhere else. Projects, issue types and priorities are matched against your Jira site exactly (key or name, case ignored). RepeatWise never guesses: a value that does not match is an error.

### Template columns
Column names are not case sensitive, and the columns can be in any order. Unknown columns are ignored and listed in the preview. Put a cell that contains a comma in double quotes (`"report,weekly"`): a row with more or fewer cells than the header is an error.

| Column | Value | When empty |
|---|---|---|
| Name | Schedule name | The summary |
| Project key | Project key (or exact project name), for example `OPS` | The project of the page (project page only); otherwise an error |
| Issue type | Issue type name or id, for example `Task` | The project's default standard type, shown in the preview |
| Summary | Summary of each issue; [variables](variables.html) such as `{{date}}` work | The name |
| Description | Plain text. Blank lines separate paragraphs | No description |
| Frequency | A sentence, for example `every Monday at 9am` or `last business day of the month at 17:00` (the same phrases as Quick Start's **Describe it**) | Use **Preset** instead |
| Preset | `daily`, `weekdays`, `weekly`, `every-2-weeks`, `monthly`, `monthly-last-business-day`, `quarterly`, `yearly` or `custom` | Use **Frequency** instead |
| Every | Custom preset only: a number and a unit, for example `3 months` (days up to 365, weeks 52, months 24, years 10) | |
| On | A weekday (`MO` to `SU`, or `Monday`) for weekly rules, or a day of the month (`1` to `31`) for monthly, quarterly and yearly rules | The weekday or day of the start date |
| Weekend rule | `keep`, `before` (the Friday before) or `after` (the Monday after). Not for `weekdays` and `monthly-last-business-day` | `keep` |
| Time | `HH:mm`, 24-hour | `09:00` |
| Time zone | IANA time zone, for example `Europe/Paris` | Your browser's time zone |
| Start date | `YYYY-MM-DD`, in the schedule's time zone. Yearly rules repeat on this month | Today |
| Labels | Comma separated, no spaces inside a label: `report,weekly` | No labels |
| Assignee | `owner` or `default` (Jira's default assignee for the project, unassigned if the project has none; `unassigned` is accepted too) | `default` |
| Priority | Priority name, for example `High` | Jira's default priority |
| Holiday country | Optional 2-letter code, for example `FR`. Holidays move with the weekend rule; `weekdays` skips them | Weekends only |

Use either **Frequency** or **Preset** (with **Every** and **On**) on a line, not both. If the sentence gives a time or a start date and the column gives another, the line is an error. A sentence the parser does not fully understand is an error, never a guess: use the preset columns for it.

### Examples
```csv
Name,Project key,Issue type,Summary,Frequency,Preset,Every,On,Weekend rule,Time,Time zone,Start date,Labels,Assignee
Weekly team report,OPS,Task,Weekly report {{date}},every Monday at 9am,,,,,,Europe/Paris,2026-11-02,"report,weekly",owner
Month-end close,FIN,Task,Close the books for {{month}},,monthly-last-business-day,,,,17:00,Europe/London,2026-11-01,finance,default
Server patching,OPS,Task,Patch the servers,,custom,3 months,15,after,08:00,America/New_York,2026-11-15,,
```

### Importing an export
A file made with **Export** can be imported again, for example to copy schedules to another project (change the project column) or another Jira site. Its **Rule** column is read as the frequency sentence and its **Time zone** and **Labels** columns are used; the other columns are ignored. An export has no issue type or summary, so the project's default type is used and the summary is the name; add **Issue type** and **Summary** columns to choose them. Rules that the sentence cannot express (several weekdays, a position such as "the 2nd Tuesday", end dates, advanced rules) and weekend or holiday settings do not come back: those lines show an error, or get the default weekend rule. Recreate them in the wizard.

## Export run history
- **One schedule:** on its detail page, under **Run history**, choose **Export run history**.
- **All schedules (administrators):** on the administration page, under **Occurrence log**, choose **Export run history**.

Pick a period (dates in your time zone, at most 12 months), then **Prepare file**. Each line is one run: schedule, project, planned time in UTC and in the schedule's time zone, status, issue key, whether it was a **Run now**, and the error or reason text. Runs are listed oldest first. You see the runs of the projects you can browse; administrators see every schedule.

A file holds at most 10,000 runs. When more exist, the dialog says the file is **truncated**: export a shorter period to get the rest. Runs of deleted schedules, and skipped dates that never became a run (holiday or exception skips, shown in the occurrence log), are not included.

## Download or copy
The file is built in your browser. **Download CSV** saves it to your device; **Copy CSV** copies the same content to your clipboard, to paste into a spreadsheet, in case your browser blocks downloads from Jira apps. Nothing is sent anywhere else.

The file is UTF-8 with a byte order mark, so Excel shows accents correctly. A cell that starts with `=`, `+`, `-` or `@` gets a leading `'` so that a spreadsheet does not run it as a formula.

## Feedback
**Feedback** (on the schedule list and the administration page) asks "How is RepeatWise working for you?" and offers:

- **Rate RepeatWise on the Marketplace**: opens the Atlassian Marketplace reviews in a new tab.
- **Suggest a feature** and **Report a problem**: open your own email app with a short template addressed to RepeatWise support. You review and send the message yourself. The template contains only the app version: no schedule content and no account id.

An option appears only when its destination is set up; the button is hidden when none is.
