| Where | What | Status |
|---|---|---|
| Global page (Apps menu, "RepeatWise") | Your schedules across the projects you can browse | Available |
| Project page (project sidebar, "RepeatWise") | Schedules of that project; new schedules start on that project | Available |
| Administration page (Jira settings, "RepeatWise") | Summary tiles, settings, schedules in error, occurrence log. Jira administrators only | Available |
| Issue action "Make this issue recurring" | Open Quick Start filled from the issue; **More options** opens the wizard | Available |
| Issue panel on generated issues | Show the schedule, occurrence number and next run, with a link to the schedule | Available |

The issue action copies the project, issue type, summary, labels, priority, components, unreleased fix versions and parent where available, and the description exactly as it is in the issue: formatting, checklists, tables, panels, images and mentions included (content the editor cannot edit is kept as is and shown read-only). The assignee is copied when that person can still be assigned in the project. Mentions in the description notify people every time an issue is created: RepeatWise warns you about them. Attachments are not copied. Tick **Also link each new issue to KEY** to give every new issue a *Relates* link to the source issue.

## The schedule list and detail page

The list starts with three tiles: how many issues the active schedules will create **Today**, **Tomorrow** and **This week** (the next 7 days), counted in your time zone. Each card shows the schedule's name, status, a **Healthy** or **Needs attention** badge, its timing, next run and last run in the schedule's time zone, and a hint when the schedule skips while the previous issue is still open. Select a schedule's name to open its detail page. You can search by name, project, label or frequency, filter by project and by status (**All**, **Active**, **Paused**, **With issues**), and under **More filters** show only **Mine** or one label. Each card has **Edit** and **Pause** or **Resume**; **Duplicate** and **Delete** are in its **More actions** menu. To pause or resume several schedules at once, select them (or **Select all matching**) and use **Pause selected** or **Resume selected**: each schedule is checked on its own, and the result lists any that failed. Long lists show 50 schedules at a time; **Show more** adds the next ones.

The detail page starts with a breadcrumb (RepeatWise > Recurring schedules > the schedule's name), the schedule's name and one line taken from the issue description (or its summary). A header card shows the status, a health badge (**Healthy**, or **Needs attention** with an orange card when the schedule has a problem or its last run failed), the recurrence, the project and the next run. When the schedule acts on the previous issue (for example **If previous issue is still open: Skip**), the card says so. The card has **Run now**, **Edit**, **Pause** or **Resume**, and a **More actions** menu with **Duplicate** and **Delete**.

**Upcoming runs** lists the next planned runs (date, then time and time zone city); **Run history** lists the last 20 occurrences, newest first, with the date, a link to the created issue and a status (Created, Skipped, Failed or Pending), plus the reason for a skip or a failure. Each list shows four rows; **View all** shows the rest.

**Run now** creates this schedule's issue immediately, after you confirm. The regular plan does not change: the next run stays where it was. It works on an active or a paused schedule (a paused one stays paused), when the app license is active, for the schedule's owner or a Jira administrator. The issue is created by the schedule owner, exactly like a planned one: the variables (such as `{{date}}`) and the due date use today's date in the schedule's time zone, and the sub-tasks, the sprint and the comment or transition on the previous issue are applied. The rule "skip if the previous issue is still open" does not stop a run you asked for. The run shows in **Run history** with a **Run now** tag. A second click in the same minute does not create a second issue, and a new run is possible one minute after the previous one. Run now is not available in the minute the schedule's own run is planned. Run now makes one attempt: if Jira refuses the issue, the run is marked **Failed** with the reason, and you can try again. If Jira does not answer clearly (for example it is unavailable), the run stays **Pending**: a few minutes later RepeatWise checks whether Jira created the issue and records it, or marks the run **Failed** so you can run it again. It never creates a second issue for the same run.

**Duplicate** opens a new, prefilled schedule in the wizard. If the source start date is in the past, the copy keeps the rule's rhythm and starts on the next aligned date (or today if none remains), rather than restarting its interval from today. The copy is named **Copy of** followed by the original name. A future start date stays as set. If an end date is before the copy's start date, the end rule is cleared. Review the copy and select **Save** to create it. Individual skipped or moved dates are not copied.

| Status | Meaning |
|---|---|
| Active | Running. If the last attempt failed, a warning shows the retry time. |
| Paused | Not running. Resuming starts from now: paused periods are not caught up. |
| Error | Stopped. The message says why. Fix it and save the schedule to restart. |
| Ended | The rule has no more occurrences. |

## Calendar

Select **View calendar** next to the Today, Tomorrow and This week tiles to see every run on a calendar. On a project page it shows only that project's schedules; **View in calendar** under a schedule's **Upcoming runs** shows only that schedule (**Show all schedules** widens it). Choose **Month**, **Week** or **Agenda** (a list by day of one week, Monday to Sunday; the default on narrow screens), move with **Today** and the arrows (by month, or by week in Week and Agenda), and filter by project, **Mine** or **Everyone**, and label. Paused schedules are left out unless you turn on **Include paused schedules**. All times are in your time zone, shown at the top.

Past days show what happened, with the status (Created, Skipped, Failed or Pending) and the issue key. Today and later days show the planned runs, each in its schedule's color; a run created early shows on its creation day, with the due date in its details. A run skipped for a weekend, holiday or exception is shown struck through, with the reason. A month day shows three runs, then **+N more**: select the day (or press Enter on it; the arrow keys move between days) to list all its runs with links to the issue and to the schedule. When a period has too many runs to show, a message says some are not shown: filter to see fewer schedules. **Back** returns to where you opened the calendar; where Jira supports it, your browser's Back button does too.

## Finding generated issues
Each created issue carries a property `recurrence` with `scheduleId`, `occurrence` and `plannedAt`. In JQL:
`issue.property[recurrence].scheduleId = "<schedule id>"`.
