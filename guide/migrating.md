Three guides: Jira's built-in "Set to recur", The Scheduler, and Recurring Tasks. RepeatWise cannot read the rules of another tool: no app can read Set to recur rules, and other apps keep theirs to themselves. Either recreate each rule in the wizard (or with **Make this issue recurring** on an existing issue), or list your rules in a spreadsheet and [import them as CSV](export-and-feedback.html#import-schedules), up to 200 at a time.

## Before you start (all sources)
1. List your existing recurring rules: name, project, issue type, frequency, time, assignee, labels.
2. Create the RepeatWise schedule (see [Getting started](getting-started.html)) and check the **next 10 dates** on the Review step against the old rule.
3. Run both in parallel only if you can tolerate duplicates for one cycle, otherwise pause or delete the old rule just before the first RepeatWise date.
4. Set the start date to the first date you still need. RepeatWise never creates issues for dates before the start date.

## From Jira "Set to recur"
Set to recur is a Jira feature, not an app, so nothing needs to be uninstalled. Rules are hidden automation rules that clone an issue.

There is no automatic import: Jira gives apps no way to read Set to recur rules. With more than a few rules, a spreadsheet is the fastest way:

1. Click **Import** on the RepeatWise schedule list (**Import from CSV** when the list is still empty), then **Download template**.
2. For each recurring issue, add a line: name, project key, issue type, summary, description, and the frequency in words (for example `every weekday at 9am` or `every 2 weeks on Monday`). Set **Time zone** and **Start date** to the next date you want.
3. Import the file, read the preview, fix the lines with errors, then **Create**.
4. Turn recurrence off on each source issue in Jira, so only RepeatWise creates issues.

See [Import schedules](export-and-feedback.html#import-schedules) for every column.

Steps, one rule at a time
1. Open an issue that recurs and note its **frequency**, the fields you rely on, and the copied children.
2. In RepeatWise, click **New schedule**. Pick the same project and issue type; copy the summary and description into the fields. Add variables such as `{{month}}` if you want distinct titles.
3. Set the frequency. Monthly, quarterly and business-day patterns are available; set the time and time zone explicitly.
4. Set the start date to the next date you want.
5. On the source issue, turn recurrence off in Jira so only RepeatWise creates issues.

What is different
- Issues are **created from a stored template**, not cloned from an existing issue. Attachments, links, and child issues are not copied. Sub-task templates saved in the wizard are created under each new issue. Parent and custom fields are set under *Additional fields* in the wizard.
- Issues are created **as the schedule owner**, who becomes the reporter and needs "Create issues".
- The time of day and time zone are yours to choose.
- RepeatWise runs on its own scheduler. It is not counted by your automation rules quota; it does not use automation rules.
- Assignee: the project default (Jira's default assignee for the project, unassigned if the project has none) or the owner.

## From The Scheduler
1. Export or list each scheduled issue: project, type, fields, cron or wizard settings, variables.
2. Recreate each as a RepeatWise schedule. Simple cron patterns map to the wizard (for example `0 8 * * 1` is Weekly, Monday, 08:00). Others can be pasted as an [advanced rule](frequencies.html#advanced-rules) (at most 24 issues a day, 60 minutes apart).
3. Translate variables using the table below.
4. Add a holiday country and policy if you handled holidays by hand.
5. Disable the old scheduled issue after checking the 10-date preview.

Variables
| Typical variable | RepeatWise |
|---|---|
| Current date | `{{date}}` or `{{date:FORMAT}}` |
| Month, year | `{{month}}`, `{{year}}` |
| Quarter | `{{quarter}}` (Q1 to Q4) |
| Week number | `{{week}}` |
| Day of the month | `{{day}}` |
| Due date | `{{due}}` |

Check the exact names your version used; unknown variables are left as typed, which makes leftovers easy to spot in the preview.

What is different
- Schedules are per project and are listed in the project's RepeatWise page.
- Holiday calendars, month-end rules and early creation are built in.
- Cron rules can be pasted as [advanced rules](frequencies.html#advanced-rules); rules that run more often than hourly must be slowed down. Sub-task templates are created under each new issue.

## From Recurring Tasks
1. List each recurring task: project, type, frequency, time, time zone, assignee.
2. Recreate it in RepeatWise, entering the **time zone explicitly** on the When step.
3. Compare the 10-date preview, including days around a clock change, with what you expect.
4. Delete or pause the old task once the first RepeatWise issue has been created (or just before it is due).

What is different
- Issues are created as the schedule owner (the reporter). The owner needs "Create issues".
- Sprint assignment is built in: pick a board with sprints, and choose Backlog or Next planned sprint when no sprint is active.
- Failures are retried and shown in the list and administration page. See [Errors](errors.html).

## Checklist after migrating
- [ ] Preview matches the old rule
- [ ] Old rule paused or removed
- [ ] Owner has "Create issues" in the project
- [ ] First issue created within 5 minutes of the target time
